---

📚 Lecture Structure

Each lecture has three components.

"README.md"

A short overview of the lecture containing:

- Topics covered
- Important concepts
- Algorithms and data structures introduced
- Related implementations
- Connections to problem solving
- Key takeaways

The README acts as the map for that lecture.

---

"notes.md"

My detailed notes from the lecture.

These focus on understanding:

- The intuition behind the concept
- How the algorithm works
- Examples
- Important observations
- Time and space complexity
- Trade-offs
- Common mistakes

The goal is to explain the material in a way that I can return to later and understand without rewatching the entire lecture.

---

"implementations/"

Algorithms and data structures are implemented here while studying the lecture.

The purpose is to move from:

Theory
   ↓
"How does this actually work?"
   ↓

Rather than treating algorithms as black boxes, I want to understand what is happening underneath.

🔬 From Theory to Implementation

When learning an algorithm or data structure, I try to answer four questions:

1. What is the idea?

What problem is this technique trying to solve?

2. How does it work?

What is happening step by step?

3. How do I implement it?

Can I build it myself without treating it as a black box?

4. How efficient is it?

What are the time and space costs?

Concept
   ↓
Intuition
   ↓
Implementation
   ↓
Complexity
   ↓
Trade-offs
